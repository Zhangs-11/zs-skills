# clarify-before-action

> 最贵的返工，往往不是代码写错了，而是一开始做的就不是用户真正需要的东西。

`clarify-before-action` 会在复杂任务动手前先只读调查，再通过一次一个问题的苏格拉底式追问，把背景、需求、痛点、范围、约束和验收标准梳理清楚。只有你确认双方理解一致后，Agent 才能开始实现。

## 安装

```bash
npx skills add Zhangs-11/zs-skills --skill clarify-before-action
```

查看仓库中可发现的 Skill：

```bash
npx skills add Zhangs-11/zs-skills --list
```

安装后新开一次 Claude Code、Codex 或其他兼容 Agent Skills 的会话。

## 你可以这样说

- “帮我实现这个需求，但先别写代码，先把背景、需求和痛点问清楚。”
- “我想改这个流程，你一次只问我一个问题，确认理解后再动手。”
- “先只读调查现有实现，再把你理解的范围和验收标准给我确认。”

## 你会得到什么

```text
只读调查现有事实
        ↓
一次追问一个关键问题
        ↓
整理背景、需求、痛点、范围与验收标准
        ↓
复述拟执行内容和明确不做的事项
        ↓
等待用户确认
        ↓
确认后才开始实现
```

它不会把每个简单操作都变成长访谈。只有任务存在实质性歧义、多个合理方向或较高返工风险时才会进入完整澄清流程；能从代码、配置和文档查明的事实，不会反过来让用户回答。

## 前置条件与边界

- [ ] 使用支持 Agent Skills 的工具，并安装 `first-principles-adversarial-review` 作为推理底盘。
- [ ] 如需调查项目事实，为 Agent 提供代码、配置、日志和文档的只读权限。
- [ ] 澄清期间只允许只读调查，不允许修改代码、配置、文档或数据。
- [ ] 用户确认任务范围不等于授权删除、提交、推送、部署或数据库写入；这些操作仍按各自规则单独确认。

本 Skill 没有 Python、Node.js 或外部 API 依赖。

## Troubleshooting

| 问题 | 原因 | 解决方法 |
|---|---|---|
| Agent 没有先澄清就开始写 | 当前会话尚未刷新，或任务被判断为简单一步操作 | 新开会话，并明确说“使用 `$clarify-before-action`，确认后再动手” |
| 一次问了很多问题 | Agent 把澄清当成一次性问卷 | 明确要求“每轮只问一个最关键的问题，并等待回答” |
| 追问一直不结束 | 没有以可执行信息是否充足作为停止标准 | 要求先复述背景、需求、痛点、范围和验收标准，再指出还缺哪一项 |
| 问了代码里已经能查到的内容 | Agent 未优先做只读调查 | 提供工作区并强调“能自己查明的事实不要问我” |

完整执行方法见 [SKILL.md](SKILL.md)。
