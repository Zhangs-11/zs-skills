# leader

> 一句话目标交给 agent，最常见的结果不是“它不会做”，而是它替你猜错了范围、事实和验收标准。

leader 会先检查代码库与外部事实，再把模糊想法整理成一个执行 agent 能独立跑完的目标任务书。任务书包含动机、边界、关键决策、执行路径和防作弊验收，控制在可直接粘贴的长度内。

## 安装

```bash
npx skills add Zhangs-11/zs-skills --skill leader
```

## 你可以这样说

- “帮我把这个想法拆成 agent 能执行的目标。”
- “写一份可直接交给 Codex 的任务书。”
- “先看仓库，再把这个重构需求拆清楚。”
- “把这项调研拆给几个 agent 并行。”

## 你会得到

- 已核验的代码库现状与必要外部事实
- 一轮集中且不超过 5 个的关键决策问题
- 4000 字符以内、可直接粘贴执行的任务书
- 白名单边界、完成条件和可复跑验收命令

## 边界

- 此 skill 负责编写和验收任务书，不代替执行 agent 完成任务。
- 需要并行拆分时应由用户明确选择；不会擅自扩大范围。
- 无法验证的事实会标记为假设，不写成确定结论。

## Troubleshooting

| 问题 | 解决方法 |
|---|---|
| 任务书超过输入限制 | 缩小目标或拆成相互独立的任务 |
| 验收命令是假绿灯 | 先在当前仓库实测命令和基线，再写入任务书 |
| 执行中不断需要问用户 | 把缺失决策集中到开工前一轮确认 |

完整任务书结构见 [SKILL.md](SKILL.md) 与 [references/anatomy.md](references/anatomy.md)。
