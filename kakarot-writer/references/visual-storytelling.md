# 公众号解释型图文

用于公众号解释、教程、方法、对比类文章，以及用户明确要求少文字、图解或流程图的内容。个人叙事和情绪文章不强制图解；图不能减少理解成本时保留文字。以下尺寸和信息预算是本工作流的起始值，不是微信官方限制，也不是传播效果保证。

## 先分配信息，再写正文

动笔前逐节确定：读者的问题、唯一结论、依据、由文字还是图承担，以及图出现后可以省去哪些段落。流程与关系优先图解；判断、原因、例外、来源和作者经历用文字。把这份简短分工交给 human-writing，不能先生成完整长文再补装饰图。

解释型图文以短引入、若干独立理解单元和简短收尾组织。每个单元回答一个问题，以结论式标题、图和一至两段补充为起点，不机械套相同版式。用户要求轻阅读时，可从约 800～1200 汉字正文开始，图中文字也计入阅读负担；材料更复杂时拆主题或补必要解释，不通过缩字和长图藏文字。

## 按关系选图

| 要帮助读者看懂什么 | 图形与关键约束 |
|---|---|
| 模块归属、层次、依赖 | 结构图；包含、调用、读取用不同边或标签，不能用箭头假造执行顺序 |
| 先后步骤、条件分流 | 纵向流程图；标明条件和出口，短箭头代替长段落 |
| 谁做、在哪里交接或等待 | 双泳道图；角色横排、时间向下，跨泳道箭头表示真实交接 |
| 请求往返与事件次序 | 时序图；参与者多于手机能容纳时拆成主流程与局部 |
| 两个方案的差别 | 前后对比或同维度小图；宽表改上下对照，不能把段落塞进色块 |
| 数量变化 | 数据图；标明单位、基线、范围和来源，没有数据不画统计图 |
| 证明来源或实际界面 | 真实截图；选与结论有关的区域，保留身份与上下文，不重绘成假 UI |

每图只有一个主要结论。优先 4～7 个关键节点、每节点一至两行短标签；超出时先合并非关键步骤或拆图。数字是起点，不是配额。编号清单即使导成 PNG，也不是结构图或流程图；真正的图需要让位置、连线、分组或尺度承担信息。

## 图文互补

图后只补原因、限制或例外，不把所有节点再叙述一遍。必要的简短文字摘要和图片 alt 保留，帮助无法看图的读者理解结论；关键风险、可复制代码、链接和操作参数不能只藏在图片里。

不要为了提高图片占比补无信息的图。概念图不是运行记录，规则推演不是实测；图内的箭头、次数和判断与正文共用同一事实源。

## 公众号手机适配

- 主阅读方向自上而下，不依赖横向滑动、点击放大或交互才能理解。泳道通常保留两个角色，更多角色拆局部。
- 正文图以 900～1080 px 宽导出 PNG；保留 Mermaid、D2、SVG 或 HTML/CSS 可编辑源。SVG 可作中间产物，公开母稿引用已渲染图片，不交付等待平台执行的 Mermaid 代码块。
- 在真实正文容器宽度下检查，不仅看原图。用 360 px 和 390 px 视口预览整篇，考虑左右边距；主要标签显示后以约 14～16 CSS px 为起点。换算为“源字体 × 显示宽度 ÷ 源图宽度”，分辨率高不等于字可读。
- 单图优先在一屏左右讲清。超高、过宽、交叉线过多时重排或拆图，不靠不断增高画布、缩小字体来消除溢出。
- 正文使用原生短段落和小标题；只把需要二维关系的部分做图。截图与解释图不必统一成社交海报尺寸，公众号正文也不照搬 PPT 或小红书卡片。

## 制作与交付

优先复用当前可用工具，不为一张图安装整套产品：简单流程/时序用 Mermaid，复杂分组可选 D2，强调中文排版或手机泳道布局时用 SVG 或 HTML/CSS，再通过浏览器导出 PNG。封面仍走 delivery.md 的独立流程。

制作后先沿一个真实或明确标注的示例检查节点与交接，再检查手机尺寸的标签、连线、裁切和滚动。新图不合格时返工，不能仅交占位符并称图文稿已完成。公众号后台未验收时，只称本地窄屏预览通过。

终审做两次消融：去掉图，如果理解不受影响就删掉该图；去掉图旁逐项复述，如果关键信息不丢就删掉重复文字。完成条件是图确实承担信息、文字不重复、关键事实与边界仍可获得、手机无需放大能理解主线。

## 参考与实现选择

以下一手资料于 2026-09-07 核对，按需要查阅，不作为每篇文章的前置阅读：

- [NN/g：How Users Read on the Web](https://www.nngroup.com/articles/how-users-read-on-the-web/)：可扫描文字、意义明确的小标题、一段一个想法。研究场景不是微信公众号，不迁用其百分比作完读率承诺。
- [NN/g：Photos as Web Content](https://www.nngroup.com/articles/photos-as-web-content/)：承载相关信息的图片与装饰图片区别。不是“图片越多越好”的依据。
- [W3C：Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)：窄屏、单列和减少双向滚动；图表存在二维例外。本工作流的 360/390 px 是编辑验收值，不是 WCAG 合规证明。
- [Mermaid](https://github.com/mermaid-js/mermaid) / [mermaid-cli](https://github.com/mermaid-js/mermaid-cli)：文本生成流程、时序等图，CLI 可导出 SVG/PNG/PDF；自动布局仍须检查中文标签和缩放。
- [D2](https://github.com/d2lang/d2)：文本描述对象、分组与连线；复杂结构的备选，不默认新增依赖。
- [doocs/md](https://github.com/doocs/md)：Markdown 转微信图文，支持 Mermaid/PlantUML；编辑器支持不等于微信原生运行脚本，最终图片、复制或上传结果仍须验收。私稿不自动上传公共编辑器或图床。
