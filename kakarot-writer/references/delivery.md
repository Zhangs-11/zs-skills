# 完整长文交付

用户说“帮我写篇文章”时，默认按本文件完成全部交付。生成不等于发布，外部写入仍需用户明确要求。

## 主稿

交付一个平台中性的 Markdown 内容母稿。公众号、知乎、博客、掘金和B站专栏同步时，标题、正文、核心图片和核心判断保持一致。

小红书、抖音和B站视频也使用这份母稿作为唯一内容源。它们可以调整标题长度、段落密度、口播节奏、字幕和画面顺序，但事实、案例、核心判断、作者态度和来源都必须回指母稿，不能再写一套内容。

小标题按材料决定。强叙事可以一口气写到底；经验方法和信息密集的文章可以用 `##` 分区。不要为了套公众号格式制造小标题。

只使用各平台都能稳定渲染的基础 Markdown。重要判断可以克制使用 `**加粗**`，一篇通常不超过三到五处；不要使用 `==高亮==`、平台私有组件或依赖特定博客引擎的语法。

## 标题

正文完成后给出三个候选：

1. 冲突型，突出真实存在的张力。
2. 发现型，突出作者通过经历或研究看到的新东西。
3. 收益型，告诉读者读完能解决什么问题。

推荐其中一条，并说明一句选择理由。标题必须被正文完整兑现，不能暗示不存在的实测、内幕和极端结果。

## 图片与截图

引用推文、GitHub issue、官方公告、产品页面、研究报告和新闻原文时，使用：

```markdown
[插图：用户截图 - 页面或内容说明]
> GitHub地址：github.com/owner/repo/issues/123
```

来源前缀写明平台，如 `X推文地址`、`GitHub地址`、`官方公告地址`、`论文地址`。文章末尾提供截图清单，列出位置、用途和完整链接。

先判断图片承担的是证据、解释还是氛围作用：

- 产品体验、教程、新闻、数据、评测和工具文章优先使用真实截图、实拍照片、官方图和原始页面；证据图不能被 AI 图替代。
- 抽象概念、趋势判断和技术原理解读可以使用 AI 图解释机制或建立视觉隐喻，但不能让读者误以为它是真实产品、实验现场或数据结果。
- 正文 AI 图只在确有解释价值时使用，一篇通常不超过一至两张。已有截图足以讲清楚时不额外添加装饰性 AI 图。

不要生成假 UI 代替真实页面，也不要在 AI 图中生成产品 Logo、中文标题、数据和需要被读者当真的界面文字。

## 封面

完整文章默认生成：

- `21:9` 微信公众号主封面。
- `1:1` 分享封面。

若 `guizang-social-card-skill` 可用，按文章类型选择素材路线：

- 产品发布、工具体验、教程和评测：优先使用官网、官方文档、公告、GitHub、真实产品截图或作者实拍，并把外部素材来源写入 `assets/SOURCES.md`。
- 抽象概念、趋势判断和技术原理解读：现实素材不足以表达核心冲突时，默认选择 AI 生成路线，无需重复询问 A/B/C。这是张硕已经确认的长期偏好。

AI 封面使用两段式流程：

1. 优先调用当前可用的图像生成工具，生成无字、无 Logo、无假 UI 的主题主视觉；提示词围绕文章核心冲突、视觉隐喻、主体位置和标题安全区编写。
2. 再由 `guizang-social-card-skill` 使用 HTML/CSS 添加标题、作者信息和必要标注，分别编排 `21:9` 与 `1:1`，不要让图像模型一次性生成带中文标题的成品海报，也不要机械裁切复用。

图像生成工具不可用时，优先用可验证的真实素材完成封面；两者都不足时才使用纯排版封面，并在交付说明中说明限制。无论采用哪条路线，封面视觉都必须服务于文章真实结论，不能虚构产品能力、实验结果或现场。

## 跨平台尾部

正文默认使用跨平台通用尾部，不出现只适用于微信的“点在看”“星标公众号”和“公众号推荐机制”。根据文章选择一种：

- 提问互动，邀请读者分享自己的经历。
- 价值确认，邀请点赞、收藏和评论。
- 克制收尾，正文已经有足够余韵时只保留作者信息。

默认作者信息：

```markdown
> / 作者：卡卡罗特
> / 投稿或爆料，请联系邮箱：19331922086@163.com
```

用户明确要求公众号专属版本时，才追加微信平台 CTA。

## 最终交付顺序

1. 推荐标题与两个备选标题。
2. 完整 Markdown 正文。
3. 封面文件或可点击路径。
4. 截图清单与关键来源。
5. 必要的事实确认项。

默认不附内部提纲和机器质检报告。
