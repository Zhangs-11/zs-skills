# kakarot-writer

> 不是给文章撒几句口头禅，而是把「谁在说、凭什么说、说完交付什么」变成一套稳定工作流。

`kakarot-writer` 是 Kakarot 的个人长文总调度 Skill。它负责作者位置、选题判断、真实材料、个人风格、配图、封面和最终交付；正文由通用的 [`human-writing`](../kakarot-human-writing/) 生成，公众号候选标题由 [`bigpeng-hot-gzh`](https://github.com/BigPengSays/bigpeng-hot-gzh) 生成，再由本 Skill 按正文事实边界筛选。

成稿以公众号首发为基准，同时作为知乎、博客、掘金、小红书、抖音和B站的唯一内容母稿。长文平台可以原文同步；短图文与视频只做形态适配，不另起观点和素材。

![使用官方真实素材生成的公众号封面示例](docs/assets/cover-example.png)

## 安装

建议同时安装个人调度和通用正文引擎：

```bash
npx skills add Zhangs-11/zs-skills --skill kakarot-writer human-writing
npx skills add BigPengSays/bigpeng-hot-gzh
```

如果当前 CLI 版本一次只接受一个 Skill，分别执行两次即可。

## 你可以这样说

- “帮我写篇文章，主题是刚入职第一个月怎么过，这是我的经历和笔记。”
- “根据这个产品 brief 写一篇文章，按我的风格完整交付。”
- “把这份 PDF 和采访记录整理成长文，事实不够就先缩小题目。”
- “按我的风格续写这篇稿子，正文不要为不同平台重写。”

“帮我写篇文章”默认不是只交一段正文，而是一套可发布成品：推荐标题与备选标题、Markdown 正文、截图与来源清单、正文配图安排、`21:9` 主封面、`1:1` 分享封面和跨平台通用尾部。

## 工作流

```text
kakarot-writer
  确定作者位置与材料，通过 AI 价值门槛，再选择文章原型
        ↓
human-writing
  生成事实站得住、自然推进的正文
        ↓
kakarot-writer
  个人风格复核、截图、配图和双尺寸封面
        ↓
bigpeng-hot-gzh
  基于完整正文生成不同公式的公众号候选标题，由 writer 核对兑现边界
        ↓
同一篇内容母稿
  公众号首发，并原文同步到知乎、博客、掘金和B站专栏
        ↓
kakarot-repurposer
  派生小红书、抖音和B站视频形态稿，不改变事实与观点
```

个人风格主要从两篇真实文章提炼：以《实习了两年的应届生，想和刚入职的你聊聊，新公司第一个月该怎么过？》校准经验与方法写法，以《二十多岁，为什么我们活成了“成年的未成年人”》补充情绪、代际处境和公共议题写法。它学习的是作者位置和表达机制，不复制句子，也不会把“应届生”等旧状态固化为永久人设。

## 它怎样从你的改稿中学习

把 AI 实际交付的初稿和你确认后的终稿交给它，并说「分析我的改法，先生成候选偏好，不要直接更新长期规则」。它会先生成可追溯的段落和措辞差异，再区分事实纠错、本篇选择、平台限制与可能稳定的个人偏好。

一次改稿不会直接改写作者画像。没有明确长期指令时，同一候选至少在两篇独立作品中重复出现，且没有同等反例，才会一次向你确认一条规则；确认后才最小修改 `personal_voice.md` 并补正向、反例评测。未发布初稿、终稿和差异报告默认只放临时目录，不进入公开仓库。

具体纠错不用等到完整终稿。系统会把它记录成私有反馈事件，并按责任路由：事实与推断边界回到 writer，标题重复、内部附录、图片和链接问题回到 publisher，视觉比例与缩略图问题回到视觉流程。客观错误会同时增加回归测试；风格候选仍需跨作品证据或你的明确长期指令，避免一次对话把个人风格带偏。

你可以这样说：

- “这是 AI 初稿和我的终稿，分析我改了什么，只生成候选偏好。”
- “这条改法以后都适用，请确认它的边界，再更新个人写作规则。”
- “把最近三篇初稿和终稿一起看，找重复规律，也主动找反例。”

## AI 文章不会自动扩成长文

模型上线、开源项目和行业热点只有资料并不够。`kakarot-writer` 会先要求文章提供一手实测、机制拆解、决策依据、可复现方法或有证据的独立判断。删除产品名后仍然成立的泛趋势观点，默认不能托住一篇长文。

价值不足时，Skill 会优先补研究或最小测试；仍然没有新增内容，就缩成短讯、保留为选题备忘，或者明确建议搁置，不用重复解释凑成一两千字。

## 默认配图与封面策略

素材按文章类型选择。产品体验、教程、新闻、数据和评测以真实截图、实拍照片及官方材料作为证据；抽象概念、趋势判断和技术原理解读如果缺少足够强的现实画面，默认生成能表达核心冲突的 AI 主视觉。

AI 封面不会让模型直接生成带中文标题的完整海报，而是先生成无字、无 Logo、无假 UI 的主题画面，再由 `guizang-social-card-skill` 使用 HTML/CSS 分别编排 `21:9` 主封面和 `1:1` 分享封面。正文事实仍由真实截图和来源承担，AI 图只用于解释抽象机制或必要的视觉转场，一篇通常不超过一至两张。

## 前置条件与边界

- [ ] 安装 `human-writing`，作为正文生成引擎。
- [ ] 安装 `bigpeng-hot-gzh`，作为公众号候选标题生成器。
- [ ] 提供链接、PDF、brief、原始笔记或真实经历；材料越完整，文章越可靠。
- [ ] 如需完整的双尺寸封面，安装 `guizang-social-card-skill`。
- [ ] 文章中的亲历、采访、数据和测试结果必须有真实依据。

生成完整成品不等于发布。只有用户明确说“存到公众号”“发到草稿箱”或“发布”时，才交给对应发布工具写入外部系统。小红书、抖音和B站视频等需要改变呈现形态的内容交给 `kakarot-repurposer`，但始终使用当前母稿的事实、观点和素材。

## Troubleshooting

| 问题 | 解决方法 |
|---|---|
| 正文仍有明显模型腔 | 确认同时安装了 `human-writing`，并补充真实动作、代价、失败和判断 |
| 作者被写成固定的“应届生” | 只把用户本次提供或当前资料确认的职业阶段写进文章 |
| 各平台观点和素材逐渐不一致 | 把 Markdown 母稿作为唯一内容源；派生稿只改变长度、节奏、画面和平台元数据 |
| 封面模板化、缺少视觉钩子 | 先把核心冲突转成真实素材关系或 AI 视觉隐喻，再分别编排横版与方形封面 |
| 标题比正文结论更强 | 确认 `bigpeng-hot-gzh` 收到了完整正文和真实兑现点，再降低标题承诺或补足证据 |
| AI 新闻写得完整却没有新东西 | 先写价值契约；补实测、机制或决策依据，否则缩成短讯或搁置 |
| 根据一次改稿就改变长期风格 | 一次作品只生成候选；跨作品重复并经作者确认后才更新长期规则 |
| 私人草稿出现在公开仓库 | 初稿、终稿和差异报告默认放任务临时目录，不提交到 Skill 仓库 |

完整规则见 [SKILL.md](SKILL.md) 和 [references/](references/)。
