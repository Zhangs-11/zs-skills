# 事实字段来源：`actual` / `effective` / `final` 不得静默回退

返回体、日志、审计记录或上报中名为 `actual_*`、`effective_*`、`final_*`、`runtime_*` 的字段，必须来自它所声明的运行时事实源。请求值、默认值、本地配置和待验证回读是不同证据层，不得因为后者缺失就把前者原样填进“实际值”。

1. **分开字段**：需要同时保留时，使用 `requested_*`、`configured_*`、`actual_*` 等不同字段，不覆盖、混合或互相 fallback。
2. **显式标记证据强度**：为可能缺失的回读附加 `actual_source`、`readback_status` 或等价来源字段。回读失败时，`actual_*` 留空或 null，并记录失败原因；不得伪造一个“看起来完整”的值。
3. **用反例锁定**：测试请求值与真实回读不同、只有配置没有实际展开、回读抛错三种情况。测试应证明旧的静默 fallback 会失败，而不是把 `actual == requested` 当成兼容行为钉住。

如果真实事实不可得，结论必须标记“未验证”，相关日志不得用于排除“配置未落库、能力未装配或运行时被过滤”。
