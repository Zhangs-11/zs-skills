# Schema 广播契约 × 运行时校验：“必传”要在两层同时成立

修改 MCP 工具、OpenAPI、RPC 或其他对外 Schema 时，要分开审查“广播给生产者的契约”和“服务端真正执行的校验”。字段 description 写“必须传”不等于它已进入 Schema `required`；Schema `required` 也不证明服务端会提前拒绝。

1. **写出两层生产者与消费者**：模型、SDK、生成的 Skill 或其他调用方消费对外 Schema；服务器 transport、argument model、wrapper 和最终函数决定运行时行为。必须追到真实调用路径，不得根据框架名或测试注释推断校验顺序。
2. **用真实入口实测缺字段**：通过服务器实际使用的 `Tool.run()`、transport handler 或等价入口调用一次，分别记录 Schema 修改前后是框架拒绝还是函数内门禁命中。只直调 `.fn()` 或只断言 Schema 字典，不能证明端到端契约。
3. **必传字段默认双保险**：如果调用方必须每次显式决策，对外 Schema 应在真实消费链支持的前提下标记 `required`，函数内仍保留稳定错误码门禁，用于覆盖绕过 Schema、历史客户端和内部直调。如果不能双保险，必须用实际 transport 证据说明冲突和取舍。
4. **检查跨仓生产者**：搜索会根据 Schema、文档、模板或阶段 Skill 生成调用的仓库。实时 Schema 与固定指南不一致时，要判断调用方实际优先级，并把会让模型持续漏传的权威资料列为需同步的 finding 或建议；Review 中仍不直接修改跨仓内容。
