# explain-to-master

> “看懂了”不等于能讲清楚，更不等于遇到新问题时会用。

explain-to-master 用费曼学习法、具体 Case 走读和苏格拉底式单问题追问帮你形成可检验的心智模型。你已经有抓手时，它让你先复述；你看完分析仍似懂非懂时，它会先选一个具体 Case 从输入走到结果，再通过追问、反例和迁移测试确认你是否真的掌握。

## 安装

```bash
npx skills add Zhangs-11/zs-skills --skill explain-to-master
```

## 你可以这样说

- “用费曼学习法带我弄懂这段代码。”
- “我好像懂了微服务，但讲不清，考考我。”
- “让我能向产品同事解释这个业务流程。”
- “用反例检查我对 RAG 的理解。”
- “我看完 Review 还是似懂非懂，用同一个订单 Case 带我把调用链走一遍。”
- “先直接用一个具体例子讲清楚，讲完再一次问我一个问题。”

## 学习流程

1. 明确你最后要能做到什么，并核对真实材料。
2. 如果你缺少具体体感，先选一个真实或明确标注的示例 Case，从初始输入逐步走到最终结果；如果你已有基本理解，则先让你预测或复述。
3. 到关键分支后一次只问一个问题，只修补当前最上游的理解漏洞。
4. 用反例检查边界，再换一个新情境做迁移测试。
5. 由你重新讲一遍，直到机制、取舍和限制都能说明白。

## 前置条件与边界

- 无额外依赖；如有代码、论文或内部文档，请一并提供。
- 对可能变化的事实，应先查当前权威来源；无法核验时会标记“推断，未验证”。
- 只想要直接答案、普通摘要或代写时，不应使用此 skill。

## Troubleshooting

| 问题 | 解决方法 |
|---|---|
| 主题太大 | 先选择一个最小但完整的机制或流程切片 |
| 缺少项目专属事实 | 提供代码、文档或真实规则，避免用通用经验脑补 |
| 只看到抽象图和方法名，没有体感 | 要求进入“具体 Case 走读模式”，固定一份输入逐步说明状态与下游结果 |
| 回答变成长篇讲课 | 要求回到“我先复述，你逐步追问”的短回合模式 |

完整教学流程见 [SKILL.md](SKILL.md)。
